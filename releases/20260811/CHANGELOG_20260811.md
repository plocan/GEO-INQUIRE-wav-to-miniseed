# Release 2026-08-11 — Fix 48 dB offset in PCM_24 MiniSEED output

## Git Commit Message

```
fix: correct 48 dB amplitude offset for PCM_24 WAV files

When reading 24-bit PCM WAV files via libsndfile/soundfile, samples are
returned left-justified in a 32-bit integer container (multiplied by 256).
This introduces a systematic offset of 20*log10(256) = 48.16 dB in the
PPSD plots of the resulting MiniSEED files.

Applied correction at three points in the pipeline:
- read_wav_as_counts: right-shift PCM_24 data by 8 bits after reading
- write_flac_from_counts: left-shift native counts before writing FLAC
- flac_to_miniseed: right-shift PCM_24 FLAC data by 8 bits after reading

Also added PCM_16 support (right-shift by 16 bits) for completeness.

This ensures MiniSEED contains native counts consistent with StationXML
instrument sensitivity, eliminating the artificial spectral level shift.

Reported by: Peter Danecek (INGV/EIDA) during TA3-83-5 validation.
```

## Summary of Changes

### Problem

During the validation of MiniSEED products uploaded to EIDA, a systematic **48 dB offset** was identified between products generated by this tool and reference workflows. The spectral content was otherwise consistent, confirming the issue was purely a scaling artifact.

### Root Cause

The `libsndfile` library (accessed via Python's `soundfile` package) returns PCM_24 samples **left-justified** in a 32-bit integer container. This means every 24-bit sample is internally multiplied by 256 (shifted left by 8 bits) to fill the int32 dynamic range. If this scaling is not corrected before writing to MiniSEED, the output data has amplitudes 256× too large, producing exactly:

```
20 × log₁₀(256) = 48.16 dB offset
```

### Fix Applied

Three modifications in `20260104_GEO-INQUIRE_wav_flac_miniseed_V12.ipynb`:

#### 1. `read_wav_as_counts()` — WAV reading
```python
if subtype.startswith("PCM"):
    data, _ = sf.read(file_path, dtype="int32")
    shift = pcm_justify_shift(subtype)  # PCM_16→16, PCM_24→8, PCM_32→0
    if shift > 0:
        data = (data >> shift).astype(np.int32)
    return data.astype(np.int32), samplerate, info, "pcm"
```

#### 2. `write_flac_from_counts()` — FLAC writing
Shift amount is derived from the FLAC PCM subtype (same mapping as the read path), and values are clipped to the container full-scale before left-justifying so int32 cannot wrap:
```python
subtype = get_pcm_subtype(nbits)
pcm_bits = pcm_container_bits(subtype)
full_scale = full_scale_counts(pcm_bits)
write_data = np.clip(data_counts, -full_scale, full_scale).astype(np.int64)
shift = pcm_justify_shift(subtype)  # PCM_16→16, PCM_24→8, PCM_32→0
if shift > 0:
    write_data = write_data << shift
sf.write(flac_file_path, write_data.astype(np.int32), sample_rate, format="FLAC", subtype=subtype)
```

#### 3. `flac_to_miniseed()` — FLAC-to-MiniSEED reading
```python
flac_info = sf.info(flac_file_path)
samples, sample_rate = sf.read(flac_file_path, dtype="int32")
shift = pcm_justify_shift(flac_info.subtype)
if shift > 0:
    samples = (samples >> shift).astype(np.int32)
```

### Impact

- **PCM_24 WAV files** (used by INFN, and most underwater acoustic recorders): 48 dB offset is eliminated.
- **FLOAT WAV files** (used by PLOCAN): the FLAC intermediate step now handles the int32 scaling correctly, producing consistent MiniSEED output.
- **No change** to the physical signal content or StationXML metadata.

### Action Required

All MiniSEED files previously generated from **PCM_24 WAV sources** should be regenerated with this updated version to ensure correct amplitude calibration in EIDA.
